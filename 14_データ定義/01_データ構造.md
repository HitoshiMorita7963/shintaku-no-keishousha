# データ構造

## 基本方針

JSONはIDを主キーとし、他データへの参照はIDで行う。

- `characters`: キャラクター
- `artifacts`: 神器
- `guardians`: 守護獣
- `skills`: 天撃・神技
- `enemies`: 敵
- `items`: アイテム
- `maps`: マップ
- `events`: イベント

## キャラクターJSONの正式構造

```json
{
  "id": "A01",
  "name": "黒馬 龍一郎",
  "class": "A",
  "age": 15,
  "entrance_number": 3,
  "role": "万能型",
  "stats": {
    "lv1": {
      "hp": 120, "sp": 55, "atk": 18, "def": 15, "spd": 18,
      "int": 18, "tec": 17, "eva": 18, "acc": 17, "luk": 18
    },
    "lv100": {
      "hp": 920, "sp": 820, "atk": 520, "def": 450, "spd": 540,
      "int": 560, "tec": 530, "eva": 500, "acc": 480, "luk": 520
    }
  },
  "artifact_id": "ART_A01",
  "guardian_id": "GUA_A01",
  "join_episode": "1",
  "notes": "キャラクターLvと神器Lvは独立。守護獣親密度は0%開始。"
}
```

## ステータスの正規キー

`hp`, `sp`, `atk`, `def`, `spd`, `int`, `tec`, `eva`, `acc`, `luk` の10個を使用する。
順序は `HP → SP → 攻撃 → 防御 → 素早さ → 賢さ → 技術 → 回避 → 命中 → 運`。

## 参照関係

`characters.artifact_id` は `data/artifacts/*.json` の `id` を参照する。
`characters.guardian_id` は `data/guardians/*.json` の `id` を参照する。

キャラクターJSONには神器名・守護獣名・属性を重複保存しない。表示時に参照先から解決することで、設定値の二重管理を防ぐ。

## 原則

ゲームロジックはJSONの存在を前提に直書きしない。データローダーと参照解決層を用意する。


## v1.2 正規データ責務

キャラクターの10ステータスは `data/characters` のみが保持する。神器・守護獣・スキル・敵等へコピーしない。神器/守護獣の所有者はキャラクターJSONのID参照から解決する。
