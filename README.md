# 神官養成学園 Claude Code 開発プロジェクト v1.3

## 目的
本フォルダは、Claude Codeに「神官養成学園」を実装させるための公式設定・仕様・データの初期セットである。

## v1.3での重要な整合性修正
- 30人一覧の「役割」の直後に、HP / SP / 攻撃 / 防御 / 素早さ / 賢さ / 技術 / 回避 / 命中 / 運の10列を正式配置。
- 一覧表はLv100時点の値を表示する。
- キャラクターJSONは `stats.lv1` / `stats.lv100` の2スナップショットを正式採用。
- ステータスキーを `hp, sp, atk, def, spd, int, tec, eva, acc, luk` に統一。
- 神器と守護獣は名称ではなく `ART_XXX` / `GUA_XXX` のIDで参照。
- 神器名・守護獣名・属性は参照先JSONを正とし、キャラクターJSONで二重管理しない。
- `data/schemas/character.schema.json` と `scripts/validate_character_data.py` を追加。

## 最重要ルール
1. ユーザーが確定した設定を最優先する。
2. 本フォルダ内で「確定」と明記された内容を、Claudeの判断で改変・再解釈・削除しない。
3. 「未確定・提案」にある内容は仮案であり、確定設定として扱わない。
4. 本作はターン制コマンドRPG。SRPGのマス戦闘にはしない。
5. キャラクターLv、神器Lv、守護獣親密度は別々に管理する。
6. 設定データとゲームロジックを分離する。
7. まず第1～2章を安定実装し、後から第3章以降を追加できる構造にする。
8. キャラクターJSONの10ステータスキーを勝手に変更・追加・削除しない。

## 読み込み順
00_開発ルール → 01_ゲーム概要 → 02_世界観 → 03_キャラクター → 04_神器 → 05_守護獣 → 06_スキル → 07_戦闘システム → 08_アイテム → 09_敵 → 10_マップ → 11_イベント → 12_ゲーム進行 → 13_UI → 14_データ定義 → data/

## Claude Codeへの実装方針
- データをJSONから読み込む。
- シナリオ進行をイベントJSONで管理する。
- 戦闘処理はデータから独立したロジック層にする。
- 未確定仕様に遭遇したら勝手に確定せず、`99_未確定・提案/` に記録する。
- 既存実装を壊す変更をする場合は、変更理由と影響範囲を記録する。
- 実装前後に `scripts/validate_character_data.py` を実行してデータ整合性を確認する。


## v1.3 データ整合性

v1.3では、データごとの責務を明確化しています。

- キャラクターの10ステータスはキャラクターJSONだけが正規保持。
- 神器一覧にキャラクターステータスを混入させない。
- 守護獣一覧にもキャラクターステータスを混入させない。
- 神器/守護獣の所有者はキャラクターJSONのID参照から解決。
- `owner_id` の二重管理を廃止。
- 全JSON、ID参照、Markdown一覧、ステータス混入を統合バリデータで検査する。

実装前に必ず:

```bash
python scripts/validate_project_data.py
```

を実行してください。


## v1.3 戦闘成長・技仕様

- SPという名称は使用せず、リソース名はSPに統一。
- 物理攻撃は攻撃力依存。
- 天撃は賢さ依存。
- したがって神器は、物理系なら攻撃力、天撃系なら賢さを必ず補正する。
- 防御力は全神器が補正する。
- 技術・命中・運・素早さ・回避はキャラクター個性に応じて補正。
- 神器基本ステータス補正は神器Lvごとに成長する。
- 神器Lvに応じて属性ダメージ倍率、クリティカル率、固有技解放を段階的に追加する。
- 神器固有技は各キャラクター4個を初期実装し、今後10個前後まで拡張可能な構造にする。
- 天撃は基本7属性×5個＋上位7属性×5個を初期実装。
- 守護獣解放時、HP/SP以外のステータスを基礎1.5倍。
- 守護獣親密度で解放倍率・属性ダメージ倍率を上昇させる。
- 守護獣固有技は各キャラクター5個、合計150個。
- 倍率は乗算によるゲームバランス崩壊を防ぐため、必ず戦闘テストで検証する。
